# NUTMEG Notion ワークスペースの地図

このファイルの目的：エージェントが「どのDB・どのページを見に行けばいいか」と「タイトルでどう探せばいいか」を、APIを叩く前に判断できるようにすること。
ID・URL・個人名・中身は載せない。IDは各自の環境で `nn find` / `nn dbs` で引き、よく使うものは `nn alias` で別名をつける。

## まず見るDB

| DB名 | 入っているもの | 主な列 |
| --- | --- | --- |
| Articles | 議事録・企画書・ハッカソン資料・勉強会メモなど、文書のほとんど（数千ページ） | name（タイトル）, Person, Date, 場所, URL, AI 要約 |
| メンバーデータベース | メンバーのニックネームと所属プロジェクト | nickname, project, about |

- 探しものは、まず Articles のタイトルから（`nn find 単語 --db <Articlesの別名>`）
- 同じ名前のDBが複数ある：Articles、タスク、局タスク、週刊進捗など。`nn dbs 名前` で更新日を見て、新しいほう（またはページ数が多いほう）を選ぶ
- 各プロダクト（FinanSu、Seeds、HPなど）は、それぞれ専用のDBやページを持っていることが多い

## タイトルの付け方の癖

- 代（期）ごとに「45th」「46th」のような接頭辞がつく。区切りは揺れる（なし・`-`・`_`・空白）
  - 例：「45thNUTMEGハッカソン…」「46th-NUTMEGハッカソン企画書ver2」「46th_NUTMEGハッカソン_チーム名」
  - なので、`nn find 46th ハッカソン` のように単語を分けて探す
- 版は「ver1」「ver2」で区別されることが多い。新しいほうを使う
- 子ページは、タイトルに代や企画名が入っていないことがある（例：企画書の下の「キックオフ用ページ」）。親ページから `nn children` でたどる

## よくある探し方

| 探したいもの | やり方 |
| --- | --- |
| あるイベントの企画書 | `nn find <代> <イベント名> 企画書` → いちばん新しいver |
| 企画書にぶら下がる当日資料（キックオフ・中間・成果発表など） | 企画書を `nn children` |
| ハッカソンの各チームのページ | `nn find <代> ハッカソン` → 「<代>_NUTMEGハッカソン_チーム名」の形のもの |
| 前の代の同じ資料（比較したいとき） | 代の部分だけ変えて `nn find` |
| 最近の議事録 | `nn db <Articlesの別名> --since YYYY-MM-DD --props Date` |
